# Аудит проекта «Шашлык Лайк × ШашлычОК»

Дата аудита: 12 октября 2026.

## Архитектура

- Frontend: React 19, React Router 7, TypeScript и Vite 7.
- Backend: один Node.js HTTP-процесс без внешнего web-фреймворка.
- Production-модель: Node.js собирает Vite-клиент, обслуживает `dist` и API с одного origin.
- Текущее хранилище: JSON по `DATA_STORE_PATH`; загрузки записываются в `public/uploads`.
- Шрифт: локальный Geologica из `public/fonts`.
- Маршруты: главная, меню, карточка товара, акции, доставка, самовывоз, избранное, корзина, checkout, подтверждение и статус заказа, о нас, контакты, admin и 404.

## Функциональные и серверные исправления

- Сервер заново рассчитывает цену заказа по каталогу.
- Количество проверяется на положительность, шаг товара и предел в 100 шагов.
- Варианты и дополнения сверяются с разрешёнными для конкретного товара; дубли дополнений отклоняются.
- В одном заказе допускается не более 100 строк.
- Создание и редактирование товара проверяет название, цену, шаг, URL изображений, категории и дополнения.
- Upload проверяет MIME, размер и сигнатуру файла, а не только Data URL.
- Вход в admin требует явно введённых логина и пароля.
- Защита владельца и RBAC подтверждены интеграционными тестами.
- Telegram-запросы имеют timeout; polling можно отключить через `TELEGRAM_POLLING_ENABLED=false`.
- Добавлен graceful shutdown для SIGTERM/SIGINT.

## Оставшиеся замечания

| Приоритет | Область | Замечание | Статус |
|---|---|---|---|
| Критический для production | Хранилище | Layero использует эфемерную файловую систему, а проект хранит заказы/пользователей в JSON и загрузки в `public/uploads` | Нужна миграция в PostgreSQL и object storage либо подтверждённый постоянный volume до запуска продаж |
| Высокий | Контент | Первые товары в локальной базе используют скриншоты вместо food-фото | Требует замены владельцем через admin; данные не менялись автоматически |
| Высокий | Telegram | Реальная внешняя отправка не выполнялась без отдельного разрешения; локально ранее был `getUpdates conflict` от второго процесса | Код и точки вызова проверены, нужен контролируемый smoke-тест с одним polling-инстансом |
| Средний | CSS | Семь исторических CSS-файлов перекрываются итоговым `light-system.css`; часть bridge-правил использует `!important` | Работает, но нужна поэтапная консолидация без визуального регресса |
| Средний | Admin | Разрушительные write-сценарии не запускались на реальной базе владельца | Покрыты изолированными integration-тестами; live smoke проводить на копии данных |
| Низкий | Производительность | Основной клиентский chunk остаётся единым | При росте приложения вынести страницы в lazy chunks; сейчас сборка проходит |

## Вывод

Критические UI-дефекты и серверная валидация исправлены. Проект можно собирать и проверять как единое Node.js-приложение. Production-деплой на Layero нельзя считать безопасным для реальных заказов, пока постоянные данные и изображения не вынесены из файловой системы runtime-контейнера.
